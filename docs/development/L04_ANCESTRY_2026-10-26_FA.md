# بررسی ناسازگاری ساختار کنترل‌ها در L04 — ۲۰۲۶/۱۰/۲۶

وضعیت: گزارش مستقیم، مرجع null را از خودِ ارائه‌دهنده تأیید کرد. آماده‌سازی
صدور برحسب تقاضا در مسیر مشترک پیاده‌سازی شد؛ پذیرش زندهٔ L04 باز می‌ماند.

## پاسخ مستقیم دریافت‌شده و اصلاح رفتاری

عامل فایل جدید مالک را خواند و با نام `provider-null-child.json` کنار شواهد
قبلی ذخیره کرد. خلاصهٔ خروجی واقعی:

</div>

```text
library declared child count = 1
library refreshed child count = 1
library refreshed child missing = 1
wire owner PID matches = 1
wire ChildCount = 1
wire GetChildAtIndex(0) = null
wire GetChildren count = 1, null entries = 1
```

<div dir="rtl" lang="fa">

بنابراین در این نوبت، خودِ سرویس یک فرزند اعلام و مرجع null برگردانده است؛
این شکست اول، ناشی از مقایسهٔ پوشش‌های والد در Python نیست. پاسخ‌های مستقیم
و کتابخانه هم‌جهت‌اند. هنوز از این اعداد به‌تنهایی نمی‌توان علت داخلیِ
فعال‌نبودن درخت را قطعی دانست.

نسخهٔ نصب‌شدهٔ بستهٔ Chrome برابر `156.0.8078.47-1` است. در
[منبع همان نسخه](https://github.com/chromium/chromium/blob/156.0.8078.47/ui/accessibility/platform/ax_platform_node_auralinux.cc)،
`CreateAtkObject` برای برنامه و قاب اصلی استثنا دارد، ولی برای سایر گره‌ها
فعال‌بودن API بومی را می‌خواهد. `AtkGetAttributes` استفاده از ویژگی‌های تکمیلی
را به AXPlatform اعلام می‌کند؛
[پیاده‌سازی مرورگر](https://github.com/chromium/chromium/blob/156.0.8078.47/content/browser/accessibility/browser_accessibility_state_impl.cc)
این درخواست را به حالت پایه و ویژگی‌های تکمیلی دسترس‌پذیری تبدیل می‌کند.
این مسیر با قابِ موجود و فرزند null سازگار است؛ وضعیت داخلی حالت اجرا در
فرایند مالک مستقیماً خوانده نشده و نتیجهٔ زنده پس از اصلاح هنوز لازم است.

خوانندهٔ مشترک قبلی نام، نقش، وضعیت و فرزندان را می‌خواند ولی ویژگی‌های
تکمیلی را درخواست نمی‌کرد. اکنون، در صورت وجود متد استاندارد `get_attributes`،
ویژگی‌های همان پنجره خوانده و مقدارشان کنار گذاشته می‌شود. هیچ نام برنامه،
برچسب آزمایشی یا پرچم راه‌اندازیِ مختص Chrome در این مسیر نیست.

برای صدور ناهمگام، در صورت مثبت‌بودن شمار و نبود اولین فرزند، حداکثر سه بار
آمادگی خوانده می‌شود و بین خواندن‌ها دو مکث ۵۰ میلی‌ثانیه‌ای وجود دارد. این‌ها
عمل یا کلیک نیستند. سپس پنجرهٔ فعال از نو انتخاب می‌شود و تمام بررسی‌های
هویت، هندسه، اجداد، وضعیت، یکتایی و پس‌شرط روی مشاهدهٔ تازه اعمال می‌شوند.
فرزندِ همچنان null اجازهٔ اجرا نمی‌دهد. شمار منفی یا ناخوانای فرزندان نیز
اکنون صریحاً به‌عنوان درخت ناقص رد می‌شود.

۲۶۴ آزمون مرتبط موفق شدند. آزمون‌های تازه، دکمه و گزینهٔ دارای صدور تنبل،
آماده‌شدن با تأخیر، null پایدار، تغییر پنجرهٔ فعال، وضعیت، PID یا والد هنگام
آماده‌سازی و شمار منفی را پوشش می‌دهند. آزمون‌های شکست اولیه، نبود مرحلهٔ
درخواست ویژگی و مسیر آماده‌شدن با تأخیر را بازتولید کردند؛ داده‌های ساختگی
جایگزین بازآزمایی واقعی ارائه‌دهنده نیستند.

بررسی‌گر کامل اصلی پس از اصلاح آماده‌سازی نیز موفق شد: نحو و Ruff، نوع‌سنجی
سخت‌گیرانه روی ۴۲۹ فایل و **۲۵۵۰ آزمون موفق در ۱۴۶٫۳۲ ثانیه**؛ دامنه کاهش
نیافت و آزمونی کنار گذاشته نشد. گزارش‌ها در
`local-data/l04-visible-control/demand-export-check/` هستند. همان محیط ایزولهٔ
بدون نمایشگر و D-Bus نشست شخصی استفاده شد؛ socketpair خصوصیِ آزمون‌ها مجاز بود.

گام بعد، آزمون فرمان روی همان صفحهٔ بی‌اثر با نسخهٔ تازهٔ KYRIN است. خروج
از سیستم یا راه‌اندازی دوبارهٔ Chrome برای این تغییر Python توصیه نشده است.
نتیجهٔ عمل و تغییر واقعی شمارنده/گزینه ثبت شوند؛ ارسال عمل به‌تنهایی موفقیت
محسوب نمی‌شود. L04 تا پذیرش زنده همچنان باز می‌ماند.

بخش‌های بعدی، مسیر رسیدن به این شاهد و ابزارهای تشخیصی قبلی را نگه می‌دارند.

## نتیجهٔ اجرای ابزار توسط مالک

عامل فایل `ancestry-diagnostic.json` ساخته‌شده توسط مالک را خواند و نسخهٔ
آن را با نام `missing-root-child.json` کنار گزارش‌های قبلی حفظ کرد.
گزارش، یک برنامهٔ مطابق، یک پنجرهٔ فعال و فقط یک گرهٔ بررسی‌شده را نشان داد.
در عمق ۱ و شاخص ۰، `ancestry_child_missing=1` است. پس هنوز به مقایسهٔ والد
فرزند نرسیده‌ایم؛ فرضیهٔ خطای مقایسهٔ پوشش والد، این اولین رد را توضیح نمی‌دهد.

همچنین `coordinate_binding=window_relative_semantic_only` با اندازه‌های
برابر و همان اختلاف مبدأ در گزارش واقعی ثبت شد. عبور از مسیر هندسهٔ نسبی
در این اجرای فقط‌خواندنی تأیید شد؛ هیچ Action زنده اجرا نشده است.

کتابخانه برای ورود به حلقه، شمار فرزند مثبت داده اما شیء اولین فرزند را
برنگردانده است. آیا پاسخ خودِ برنامه null بوده، انتقال یا تبدیل پاسخ شکست
خورده یا شمار و فهرست میان دو خواندن تغییر کرده‌اند؟ فایل فعلی این را ندارد.
[قرارداد رسمی Accessible](https://github.com/GNOME/at-spi2-core/blob/main/xml/Accessible.xml)
شمار، خواندن با شاخص و فهرست فرزندان را جدا تعریف می‌کند. آن‌ها اکنون فقط در
ابزار تشخیصی با هم مقایسه می‌شوند؛ نبود فرزند نادیده گرفته نمی‌شود.

برای فرزند غایب، ابزار یک بار شمار و فرزند را پس از پاک‌سازی دوباره می‌خواند.
سپس پاسخ مستقیم سرویس را با busctl موجود بررسی می‌کند: ابتدا PID مالک نشانی
با PID گره تطبیق داده می‌شود و فقط ChildCount، GetChildAtIndex و GetChildren
خوانده می‌شوند. نشانی‌های D-Bus، مسیر اشیا، متن و خطای خام خروجی ندارند.
هر فراخوانی یک ثانیه مهلت دارد؛ مهلت کلی helper همان هشت ثانیه باقی است.
این مسیر در اجرای معمول فعال نیست و هیچ snapshot ردشده را معتبر نمی‌کند.

| فیلد تازه | معنا |
| --- | --- |
| `ancestry_declared_child_count` | شمار اولیهٔ اعلام‌شده پیش از فرزند غایب |
| `ancestry_fresh_child_count` | شمار کتابخانه پس از پاک‌سازی |
| `ancestry_fresh_child_missing` | غیبت فرزند پس از بازخوانی |
| `ancestry_fresh_child_parent_matches` | اگر فرزند تازه برگشت، تطابق والد آن |
| `wire_owner_matches` | مالک اتصال سرویس با PID موردانتظار برابر است |
| `wire_child_count` | شمار مستقیم اعلام‌شده از سرویس |
| `wire_child_is_null` | سرویس در خواندن با شاخص، مرجع null برگردانده است |
| `wire_children_count` / `wire_children_nulls` | اندازهٔ فهرست مستقیم و تعداد مرجع null در آن |
| `wire_index_agrees_with_children` | پاسخ شاخص با همان عضو فهرست برابر است |

نبود یا خرابی پاسخ مستقیم با پرچم `unavailable` گزارش می‌شود؛ هیچ آدرسی
حدس زده نمی‌شود. پاسخ‌های واقعاً متفاوت برای انتخاب اصلاح بعدی لازم‌اند.

برای این مرحله، دستور زیر جایگزین فرمان قبلی شود؛ ظرف پنج ثانیه همان صفحه
در تمرکز قرار گیرد. خروجی هم نمایش داده می‌شود و هم ذخیره می‌شود. تغییر مدل،
خروج از سیستم یا تکرار فرمان صوتی لازم نیست؛ ابزار مستقیماً کد تازه را می‌خواند.

</div>

```bash
/mnt/ai_projects/KYRIN/.venv/bin/python /mnt/ai_projects/KYRIN/scripts/actions/inspect_visible_controls.py \
  --delay 5 --geometry --label 'Test button' --label 'Test option' \
  | tee /mnt/ai_projects/KYRIN/local-data/l04-live-check/child-transport-diagnostic.json
```

<div dir="rtl" lang="fa">

پس از این تکمیل، ۱۶۱ آزمون مرتبط موفق‌اند. علاوه بر آزمون‌ها، یک سرویس
ساختگی روی Gio.TestDBus کاملاً خصوصی با busctl واقعی بررسی شد: پاسخ شاخص
عمداً null و فهرست غیرخالی بود و ابزار اختلاف را درست گزارش کرد. این بررسی
قالب واقعی JSON را نیز تأیید کرد؛ به نشست شخصی متصل نشد و علت Chrome مالک
را اثبات نمی‌کند. فایل نمونه و نتیجه در پوشهٔ گزارش مالک نگه داشته شده‌اند.

بررسی‌گر کامل اصلی پس از تکمیل مقایسهٔ مستقیم نیز موفق شد: نحو و Ruff،
نوع‌سنجی سخت‌گیرانه روی ۴۲۹ فایل و **۲۵۴۱ آزمون موفق در ۱۴۵٫۹۹ ثانیه**.
دامنه کاهش نیافت و آزمونی کنار گذاشته نشد. گزارش‌ها در
`local-data/l04-visible-control/missing-child-wire-check/` هستند. محیط ایزولهٔ
بدون D-Bus و نمایشگر نشست شخصی حفظ شد؛ socketpair خصوصیِ آزمون‌ها مجاز بود.

بخش‌های بعدی تاریخچهٔ تشخیص قبل از این اندازه‌گیری هستند.

Click Test Button و Click Test Option با مقصد کامل، به‌ترتیب در ۲۰۶ و ۱۹۰
میلی‌ثانیه پس از متن نهایی با همان خطای ساختار شکست خورده‌اند. این نتیجه
عبور از شرط هندسه را نشان می‌دهد؛ نوع اتصال هندسی و پیدا‌شدن کنترل مقصد
را به‌تنهایی اثبات نمی‌کند. فایل اصلی شنیدن و متن ارسالی ترمینال در مسیر
نادیده‌گرفته‌شدهٔ Git ذخیره شدند:

`local-data/l04-visible-control/owner-ancestry-2026-10-26/`.

گزارش شنیدن با شناسهٔ `f7cf5ed52f514a068089d52f48fb8f39` آماده‌بودن صوت و
STT، بازگشت کارگرها و توقف صریح رابط در انتها را نشان می‌دهد. شاهدی برای
توقف خودکار شنیدن نیست. پیمایش `dispatched_unverified` نیز اثبات حرکت صفحه نیست.

## معنای خطا و عدم قطعیت

در پیمایش، شیء فرزند برای هر شاخص و سپس والد آن خوانده می‌شود. نبود فرزند
یا برابرنبودن والد برگشتی با گرهٔ جاری، پیمایش را متوقف می‌کند. پیام قبلی
این حالت‌ها را جدا نمی‌کرد. نام مقصد و مدل در این شرط دخالت ندارند.

[قرارداد والد در AT-SPI](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_parent.html)
امکان نبود والد را مشخص می‌کند و
[پاک‌سازی حافظهٔ نهان](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.clear_cache.html)
روی گره و فرزندان آن اثر دارد. بررسی
[منبع کتابخانه](https://github.com/GNOME/at-spi2-core/blob/main/atspi/atspi-accessible.c)
استفادهٔ مشروط از حافظهٔ نهان را نشان می‌دهد؛ دادهٔ قدیمی، مقایسهٔ پوشش‌های
Python یا ساختار واقعاً متفاوت، هنوز فرضیه‌اند. شرط هویت بر اساس این
فرضیه‌ها تغییر نکرده است.

## گزارش دقیق‌تر بدون تغییر شرط اجرا

ابزار فقط‌خواندنی موجود اکنون اولین رابطهٔ ردشده را با داده‌های زیر گزارش
می‌کند. نام، نشانی D-Bus و مسیر شیءِ والد یا فرزند چاپ نمی‌شوند. برابری
نشانی‌های دوردست فقط یک پرچم تشخیصی است و مجوز عمل ایجاد نمی‌کند.

| فیلد در scan | معنا |
| --- | --- |
| `ancestry_failing_depth` | عمق والدِ در حال پیمایش |
| `ancestry_child_index` | شاخص فرزندِ ردشده |
| `ancestry_child_missing` | فرزند غایب بوده است |
| `ancestry_parent_missing` | فرزند موجود ولی والد غایب بوده است |
| `ancestry_parent_same_reference` | نشانی والد برگشتی و موردانتظار: ۱ برابر، ۰ متفاوت، ۱− نامعلوم |
| `ancestry_fresh_parent_matches` | والد پس از یک پاک‌سازی و خواندن تشخیصی، با والد موردانتظار برابر شده است |
| `ancestry_fresh_parent_missing` | والد در بازخوانی نیز غایب مانده است |
| `ancestry_probe_failed` | بازخوانی تشخیصی شکست خورده؛ رد اولیه حفظ شده است |

حتی اگر خواندن دوم سازگار شود، همان snapshot رد می‌شود. بازخوانی فقط در
گزارش تشخیصی است؛ هیچ عمل یا تلاش مجدد برای کلیک انجام نمی‌شود.

از سیستم برای این ابزار لازم نیست. ابزار ورودی، کلیک، تصویر یا صوت تولید نمی‌کند.
